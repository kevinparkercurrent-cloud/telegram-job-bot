# Ссылка на исходную вакансию и редактирование отклика

Дата: 2026-08-16

## Цель

Каждая карточка вакансии должна позволять открыть исходный Telegram-пост и
отредактировать черновик отклика без ручного ввода ID вакансии. Решение должно
работать одинаково для сильных совпадений и карточек из дайджеста.

## Пользовательский сценарий

Карточка содержит кнопки:

1. `Открыть вакансию` — URL-кнопка на исходный Telegram-пост.
2. `Редактировать отклик` — запускает пошаговое редактирование.
3. `Откликнуться` — отправляет актуальный подтверждённый черновик.
4. `Пропустить` и `Не подходит` — сохраняют решение без отправки.

После нажатия `Редактировать отклик` бот показывает текущий черновик и просит
прислать новую версию одним сообщением. Следующее текстовое сообщение владельца
становится новым активным черновиком. Бот аннулирует ранее выданные подтверждения
для этой вакансии и присылает обновлённую карточку. Команда `/edit` остаётся
доступна как запасной интерфейс.

Пользователь может отменить ожидающее редактирование командой `/cancel`.
Состояние редактирования автоматически истекает через 15 минут.

## Ссылка на исходный пост

При получении сообщения Telethon формирует каноническую ссылку:

- публичный канал или супергруппа с username:
  `https://t.me/<username>/<message_id>`;
- приватный канал или супергруппа без username:
  `https://t.me/c/<internal_channel_id>/<message_id>`.

Для ссылки `/c/` из числового peer ID удаляется префикс `-100`. Такая ссылка
откроется только в Telegram-аккаунте, который имеет доступ к соответствующему
каналу или группе. Если корректную ссылку сформировать невозможно, кнопка
`Открыть вакансию` не отображается, но сама карточка продолжает работать.

Ссылка сохраняется вместе с вакансией в SQLite. Это необходимо, чтобы карточки
из отложенного дайджеста не зависели от живого объекта Telethon.

## Изменения компонентов

### Telegram ingress

`ChannelPost` получает поле `source_post_url`. `TelethonUserAdapter` извлекает
username текущего чата либо формирует приватную `/c/`-ссылку по peer ID.

### Домен и база

`Vacancy` получает необязательное поле `source_post_url`. Таблица вакансий
получает одноимённый nullable-столбец. Миграция выполняется идемпотентно при
открытии существующей базы, поэтому развёрнутый сервис не требует очистки данных.

`VacancyCard` и `DigestItem` передают сохранённую ссылку до слоя Telegram UI.

### Управляющий бот

Клавиатура карточки принимает `source_post_url`. URL-кнопка не использует
callback data. Кнопка редактирования отправляет callback
`edit_prompt:<vacancy_id>`.

`AiogramControlRuntime` хранит только краткоживущее сопоставление
`admin_user_id -> vacancy_id, expires_at`. Бот однопользовательский, поэтому
отдельное постоянное хранилище состояния не требуется. Перезапуск контейнера
безопасно отменяет незавершённое редактирование.

Следующее обычное текстовое сообщение владельца при активном состоянии
редактирования передаётся в существующий `ApprovalService.replace_draft`.
Сохранение нового текста аннулирует старые подтверждения. После сохранения бот
загружает обновлённую карточку из базы и отправляет её заново.

Команды не считаются новым текстом. `/cancel` очищает состояние. Пустое сообщение,
нетекстовое сообщение или сообщение после тайм-аута не меняет черновик и получает
понятный ответ.

## Безопасность и ограничения

- Редактировать и подтверждать отклик может только настроенный admin Telegram ID.
- Максимальная длина нового черновика — 3500 символов, чтобы обновлённая карточка
  гарантированно помещалась в ограничение Telegram 4096 символов.
- После изменения текста любое старое подтверждение становится недействительным.
- Кнопка `Откликнуться` по-прежнему применяет лимиты 5 сообщений в час и
  15 сообщений в сутки.
- Ссылка ведёт только на Telegram-пост; бот не загружает содержимое ссылки и не
  передаёт его внешним сервисам.

## Ошибки и пограничные случаи

- Вакансия удалена из канала: Telegram покажет недоступный пост; бот продолжит
  отображать сохранённую карточку.
- Основной аккаунт не состоит в приватной группе: `/c/`-ссылка не откроется;
  это ограничение доступа Telegram.
- Пока ожидается новый текст, повторное нажатие `Редактировать отклик` заменяет
  ожидаемую вакансию последней выбранной.
- Если вакансия или активный черновик удалены, бот прекращает редактирование и
  сообщает, что вакансия недоступна.
- При перезапуске сервиса незавершённое редактирование отменяется без изменения
  сохранённого черновика.

## Проверка

Автоматические тесты должны покрывать:

1. Формирование публичной и приватной ссылки на пост.
2. Отсутствие URL-кнопки, когда ссылка недоступна.
3. Передачу ссылки через pipeline, SQLite и digest.
4. Запуск редактирования только владельцем.
5. Сохранение следующего текстового сообщения как нового черновика.
6. Аннулирование старого подтверждения после редактирования.
7. `/cancel`, тайм-аут, нетекстовые сообщения и ограничение длины.
8. Повторную отправку обновлённой карточки с актуальными кнопками.
9. Сохранение обратной совместимости команды `/edit`.

После тестов выполняются `pytest`, `compileall`, сборка Docker-образа и проверка
здоровья контейнера на VPS.
